BMNR DASHBOARD — NEW TICKER SETUP GUIDE
How to get the same output files, protections, and checks for any new stock
══════════════════════════════════════════════════════════════════════════════

WHAT YOU WILL GET AT THE END
──────────────────────────────
For every new ticker (e.g. NVDA, TSLA, AAPL):
  {TICKER}/build_{ticker}_income_v1.py        ← income statement script
  {TICKER}/build_{ticker}_projection_v1.py    ← 5-year projection script
  {TICKER}/run_{ticker}.py                    ← one command runs everything
  {TICKER}/{TICKER}_MANIFEST.txt              ← source of truth, Rule 9 enforced
  {TICKER}/{TICKER}_Q{N}_{YYYY}_Income_Statement_v1.xlsx
  {TICKER}/{TICKER}_5Year_Projection_v1.xlsx

Both scripts:
  - Script-relative output paths (works anywhere, no hardcoded /mnt/... paths)
  - DATA BLOCK at top (update one section each quarter, nothing else)
  - Self-test that prints SELF-TEST PASSED before saving
  - MANIFEST-compliant (file sizes, baseline outputs, all 9 rules)

══════════════════════════════════════════════════════════════════════════════
STEP 1 — INFORMATION TO GATHER BEFORE STARTING
══════════════════════════════════════════════════════════════════════════════

Have these ready before you open a Claude session:

COMPANY BASICS
  □ Ticker symbol (e.g. NVDA)
  □ Full company name (e.g. NVIDIA Corporation)
  □ Most recent quarter reported (e.g. Q1 2026)
  □ Quarter end date (e.g. March 31, 2026)
  □ Earnings report date (e.g. May 28, 2026)
  □ Link to the earnings press release PDF (from investor relations page)

KEY FINANCIALS (from the press release)
  □ Revenue ($M)
  □ Gross profit ($M) and gross margin (%)
  □ Operating income ($M)
  □ Net income ($M)
  □ Adjusted EBITDA ($M) and margin (%) — or operating income if EBITDA not reported
  □ Adjusted EPS
  □ Prior year same quarter revenue ($M) — for Y/Y comparison
  □ Segment breakdown if available (e.g. North America / International)

PROJECTION INPUTS
  □ Full prior fiscal year revenue ($M) — base for projections
  □ Current stock price ($)
  □ Shares outstanding fully diluted (millions)
  □ Valuation method: EV/EBITDA (consumer/beverage companies)
                   or P/E (semiconductor/tech companies like AMD)

ANY ONE-TIME ITEMS TO CALL OUT
  □ Acquisitions, loading events, write-downs, divestitures
  □ Anything that makes the headline number misleading

STEP 3 — QUESTIONS CLAUDE WILL WALK YOU THROUGH
══════════════════════════════════════════════════════════════════════════════

After Claude reads the files and builds the first draft, expect to review:

INCOME STATEMENT
  □ Y/Y color for each line: green (beat), amber (grew but quality uncertain),
    red (miss), gray (flat) — Claude will propose, you approve
  □ Letter grade: A / B / C — Claude will explain the reasoning, you choose
  □ Any one-time items that should be called out in What's New tab
  □ Forward Outlook section — growth phases, upgrade triggers

PROJECTION
  □ Bull / Base / Bear revenue growth assumptions — does the range feel right?
  □ Margin expansion assumptions — realistic or too aggressive?
  □ EV or P/E multiple range — compare to sector peers
  □ Probability weights (e.g. 30% Bull / 45% Base / 25% Bear)

THE 9 RULES (enforced in every manifest — know these)
══════════════════════════════════════════════════════════════════════════════

1. NEVER rebuild from memory or scratch. Always pull from GitHub.
2. NEVER start any task without your explicit approval.
3. NEVER save a script to Drive unless self-test printed SELF-TEST PASSED.
4. NEVER upload xlsx to Drive via API — present for download only.
5. NEVER change row structure, colors, or formatting without your approval.
6. ALWAYS verify file sizes match manifest before using any script.
7. ALWAYS run self-test and show you the output before declaring done.
8. ALWAYS create a new version file for updates — never overwrite.
9. UPDATE THE MANIFEST immediately whenever anything changes — scripts,
   outputs, scores, assumptions, rules, file sizes, or output paths.
