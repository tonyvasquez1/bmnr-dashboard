══════════════════════════════════════════════════════════════════════════════

TO START A NEW TICKER — PASTE THIS, REPLACE ONLY THE TICKER SYMBOL
────────────────────────────────────────────────────────────────────

Set up [TICKER] for the BMNR dashboard.

Read these files first before doing anything else:
  NEW_TICKER_SETUP_GUIDE.txt
  celh/CELH_MANIFEST.txt
  celh/run_celh.py
  celh/build_celh_income_v1.py
  celh/build_celh_projection_final.py

Then:
1. Research [TICKER] — find the most recent earnings press release,
   pull all financials, segment breakdown, shares outstanding, and
   current stock price. Do not ask me for any of this.
2. Identify any one-time items, acquisitions, or anything that makes
   the headline numbers misleading.
3. Determine the correct valuation method (EV/EBITDA for consumer/
   beverage companies, P/E for semiconductor/tech).
4. Build all four deliverables following the CELH pattern exactly:
     {ticker}/build_{ticker}_income_v1.py
     {ticker}/build_{ticker}_projection_v1.py
     {ticker}/run_{ticker}.py
     {ticker}/{TICKER}_MANIFEST.txt
5. Run python3 {ticker}/run_{ticker}.py — both self-tests must pass.
6. Walk me through your proposed Y/Y colors and letter grade before
   committing, and wait for my approval.
7. Commit and push all files including the generated xlsx outputs.
   Update the manifest per Rule 9 before pushing.

TO UPDATE AN EXISTING TICKER EACH QUARTER — PASTE THIS
────────────────────────────────────────────────────────

Update [TICKER] for the new quarter.

Read these files first before doing anything else:
  {ticker}/{TICKER}_MANIFEST.txt
  {ticker}/run_{ticker}.py
  {ticker}/build_{ticker}_income_v[current version].py
  {ticker}/build_{ticker}_projection_v[current version].py

Then:
1. Research the most recent [TICKER] earnings — find the press release,
   pull all updated financials. Do not ask me for any of this.
2. Identify any one-time items or anything unusual this quarter.
3. Create new version files (increment v number — never overwrite).
4. Update DATA BLOCK only — do not change structure or formatting.
5. Run python3 {ticker}/run_{ticker}.py — both self-tests must pass.
6. Walk me through any proposed grade or color changes and wait for
   my approval before committing.
7. Update the manifest per Rule 9, commit and push all files.

WHAT YOU GET (same structure every time)
─────────────────────────────────────────
  {ticker}/build_{ticker}_income_v1.py
    Tabs: Income Statement / Data Sources / What's New / Forward Outlook
    Colors: Y/Y green=beat, amber=quality uncertain, red=miss, gray=flat
    Grade: A/B/C — Claude proposes reasoning, you approve

  {ticker}/build_{ticker}_projection_v1.py
    Tabs: Inputs / Projection / Probability Weighted
    Scenarios: Bull / Base / Bear with probability weights
    Valuation: EV/EBITDA (consumer) or P/E (tech/semi)

  {ticker}/run_{ticker}.py
    One command runs everything and reports file sizes

  {ticker}/{TICKER}_MANIFEST.txt
    Source of truth — file sizes, baseline outputs, all 9 rules,
    color palette, naming convention, change log

THE 9 RULES (enforced in every manifest)
──────────────────────────────────────────
1. NEVER rebuild from memory or scratch. Always pull from GitHub.
2. NEVER start any task without Tony's explicit approval.
3. NEVER save a script to Drive unless self-test printed SELF-TEST PASSED.
4. NEVER upload xlsx to Drive via API — present for download only.
5. NEVER change row structure, colors, or formatting without Tony's approval.
6. ALWAYS verify file sizes match manifest before using any script.
7. ALWAYS run self-test and show Tony the output before declaring done.
8. ALWAYS create a new version file for updates — never overwrite.
9. UPDATE THE MANIFEST immediately whenever anything changes.
