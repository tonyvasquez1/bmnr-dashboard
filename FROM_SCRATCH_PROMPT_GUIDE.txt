PHASE 1 — BUILDING THE FIRST TICKER (AMD — THE GOLD STANDARD)
══════════════════════════════════════════════════════════════════════════════

PROMPT 1 — Establish the pattern and research the company
──────────────────────────────────────────────────────────
"I'm building a financial analysis dashboard for stocks I follow.
Start with AMD. Research the most recent earnings — find the press
release, pull all financials, segment breakdown, shares outstanding,
and current stock price. Build an income statement in Excel with:
  - A DATA BLOCK at the top of the script for easy quarterly updates
  - Y/Y color indicators: green = beat, red = miss, amber = grew but
    quality uncertain, gray = flat
  - A letter grade (A/B/C) with written reasoning
  - Tabs: Income Statement / Data Sources / What's New
  - A self-test that prints SELF-TEST PASSED before saving the file
  - Output saved to the same folder as the script (not a hardcoded path)
Save as build_amd_income_v1.py in an amd/ folder."

PROMPT 2 — Review the income statement together
─────────────────────────────────────────────────
"Show me the earnings statement so we can go through it together."

  [Review each line. Ask about anything that looks unusual.]

PROMPT 3 — Challenge any one-time items
─────────────────────────────────────────
"[Line item] looks large. Is any of that one-time or non-recurring?
What would the number look like without it?"

  [If yes: "Should that line be amber instead of green given that?"]

PROMPT 4 — Agree on the letter grade
──────────────────────────────────────
"What would be a reasonable expected growth rate going forward?
Walk me through the grade — what would it take to get to A vs B?"

  [Pick the grade. Example: "Definitely B. Explain why in the file."]

PROMPT 5 — Capture the analysis in a Forward Outlook tab
──────────────────────────────────────────────────────────
"I want all this analysis captured in the file — growth phases,
what the normalized numbers look like, and what would trigger an
upgrade. Add a Forward Outlook tab. Also flag the Q1 2027 comp trap
if there is one and quantify it."

PROMPT 6 — Build the projection
─────────────────────────────────
"Now build the 5-year projection. Use the same DATA BLOCK pattern.
Bull / Base / Bear scenarios with probability weights.
Use P/E for AMD (semiconductor). Show share price low/high and CAGR
for each scenario and a probability-weighted EV target.
Self-test must pass. Save to the amd/ folder."

  [Review scenarios together. Adjust growth rates and multiples
   until they feel realistic.]

PROMPT 7 — Add the thesis tracker (AMD-specific, optional for others)
───────────────────────────────────────────────────────────────────────
"Build a thesis tracker — a scoring tool that tells me when to exit.
Score the key conditions (deal execution, ROCm adoption, margin
expansion, etc.) on a 1-10 scale with weights. Show HOLD / WATCH /
EXIT signal. Self-test must pass."

PROMPT 8 — Wire it all together
─────────────────────────────────
"Create run_amd.py that installs dependencies, runs all three scripts,
and reports the output file sizes. One command should generate
everything."

PROMPT 9 — Create the manifest
────────────────────────────────
"Create AMD_MANIFEST.txt with:
  - All current script names and exact file sizes
  - Baseline outputs to verify after every run
  - All rules including: never rebuild from scratch, never overwrite
    versions, never upload xlsx via API, always self-test first,
    always update this manifest when anything changes (Rule 9)
  - Color palette, naming convention, change log
This is the source of truth for every future AMD session."

KEY DECISIONS MADE ALONG THE WAY (understand these for any new ticker)
══════════════════════════════════════════════════════════════════════════════

VALUATION METHOD
  EV/EBITDA  → consumer brands, beverages, retail (CELH, Monster)
  P/E        → semiconductors, fabless chip, mature tech (AMD, NVDA)
  Sum-of-parts → fintech/bank hybrids, conglomerates (SoFi, Google)
  P/Book     → pure banks and insurers (JPM, BAC)

Y/Y COLOR RULES
  green  → beat expectations, durable growth
  amber  → grew but quality uncertain (loading events, one-time items,
            inorganic revenue, channel fill)
  red    → miss or decline
  gray   → flat or not meaningful Y/Y

GRADE LOGIC
  A  → strong across the board, durable growth, no structural drags
  B  → good headline numbers but at least one structural concern
       (e.g. organic growth weaker than reported, comp trap ahead,
        capital structure drag, margin questions)
  C  → meaningful problems — declining revenue, margin compression,
        thesis under pressure

RULE 9 (the most important rule)
  Update the manifest in the same commit as any code change.
  A manifest that doesn't reflect current state is worse than
  no manifest — it gives false confidence.
